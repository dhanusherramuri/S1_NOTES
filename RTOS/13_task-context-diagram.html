Same mechanism, different list

The one thing worth saying twice: led_2s and led_3s have identical saved frames above - same shape, same fields, same mechanism. Nothing about either stack tells you which one is ready and which is sleeping. Look back at the two boxes at the bottom of the first diagram - that distinction lives entirely in which linked list the TCB is threaded into, nowhere else.

The wake-up path. Every SysTick, xTaskIncrementTick() checks the head of pxDelayedTaskList - it's kept sorted by wake time, so it only ever has to look at the front. When led_3s's tick arrives, it's unlinked from the delayed list and relinked into pxReadyTasksLists[] - nothing about its saved stack frame changes in that move. It becomes eligible to run again purely by changing which list it's in.
